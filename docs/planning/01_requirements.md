# 01. 要求仕様 — モノに人格を与えるステッカー

> プロジェクトコードネーム: **PersonaSticker**(仮称)
> ステータス: Phase 0(プランニング)/ 最終更新: 2026-08-23

## 1. コンセプト

**モノに貼ると、そのモノが感情を持っているかのように振る舞うステッカー型デバイス。**

- ステッカーは貼られた対象物の環境(温度・湿度・振動・照度・放置時間など)をセンサーで観測する
- 観測値から「対象物がいまどんな状況にあるか」を推察し、**感情**を生成する
- 感情は電子ペーパー画面に**表情(顔)**として表示される
- 複数のステッカーは**Wi-Fiメッシュネットワーク**を形成し、1台のゲートウェイ経由でオンライン接続される
- ユーザーは**スマホのブラウザ**から各ステッカーの状態確認と設定変更ができる

## 2. ユースケース例

| 貼る対象 | 観測されるシグナル | 生成される感情・表示 |
| --- | --- | --- |
| 冷蔵庫 | 扉の開閉振動、庫外温度の上昇 | 開けっ放しで「さむい!はやく閉めて!」😨 |
| 観葉植物の鉢 | 温湿度の低下、照度 | 乾燥・暗所で「のどが渇いた…」「日に当たりたい」😢 |
| ギターケース | 長期間振動なし | 放置で「さみしい…遊んでよ」🥺 |
| 宅配ボックス・カバン | 突然の移動・衝撃 | 「びっくりした!」😲 |
| 窓・玄関ドア | 開閉振動、外気温 | 「今日は冷えるね」「おかえり!」😊 |

ポイント: **同じセンサー値でも、貼る対象と「性格設定」によって解釈が変わる**こと。これが「人格を与える」の核になる。

## 3. 機能要件

### 3.1 センシング(必須)
- **温度・湿度**: 環境の暑さ・寒さ・乾燥の検知
- **振動・加速度**: 移動、衝撃、扉の開閉、放置時間の検知(動作割り込みでスリープから即時起床できること)
- **照度**: 昼夜・収納中/露出中の判別

### 3.2 感情生成(必須)
- センサー値から特徴量(温度変化率、振動強度、最終接触からの経過時間など)を抽出する
- 特徴量を2次元感情モデル(快–不快 × 覚醒度)に写像し、8種前後の表情に変換する
- ステッカーごとの**性格パラメータ**(敏感さ・気質・名前)で反応が変化する

### 3.3 表示(必須)
- 電子ペーパーに表情(顔)を表示する
- 感情が変化したときのみ画面を書き換える(部分書き換えで目・口を更新)
- スリープ中も表情が表示され続ける(電子ペーパーの画像保持特性を利用)

### 3.4 ネットワーク(必須)
- ステッカー同士がWi-Fiメッシュを自律形成する
- 1台(ゲートウェイ、常時給電)がメッシュルートとなり家庭のWi-Fiルーターへ接続する
- ノードはセンサー値・感情状態を周期的にゲートウェイへ報告し、設定変更を受信する

### 3.5 スマホ連携(必須)
- ゲートウェイがWebサーバーを持ち、スマホのブラウザから `http://persona.local` でアクセスできる
- 全ステッカーの感情・センサー値の一覧表示
- 設定変更: 名前、性格パラメータ、閾値、報告間隔

### 3.6 将来拡張(任意)
- クラウド連携(外出先からの確認、プッシュ通知)
- マイク(音)による状況推察
- ステッカー同士の「会話」(隣のステッカーの感情に影響される)

## 4. 非機能要件

| 項目 | 目標値 | 備考 |
| --- | --- | --- |
| 電池駆動時間 | **2週間以上**(ノード) | ディープスリープ + 周期起床が前提 |
| ゲートウェイ給電 | USB常時給電 | メッシュルート + Webサーバーのため常時オン |
| サイズ(最終目標) | 名刺の半分程度(約 55×45mm) | 試作段階はこの限りではない |
| 厚さ(最終目標) | 10mm以下 | 薄型LiPo + FPC接続電子ペーパー |
| 台数 | 3〜10台で安定運用 | メッシュの実用規模 |
| 表示応答 | 感情変化から数秒以内に表情更新 | 部分書き換え約0.3秒 |
| セットアップ | スマホだけで完結(PC不要) | 初回Wi-Fi設定はAPモード + Web画面 |

## 5. 制約・前提

- 開発は**市販の開発ボード + モジュールで試作 → 仕様確定後にKiCadでカスタムPCB**の順で進める(→ [05_roadmap.md](./05_roadmap.md))
- 表示は電子ペーパーのため**フルカラー・滑らかなアニメーションは非対応**。表情は1bitビットマップの静止画切替(+部分書き換えによる簡易アニメ)で表現する
- Wi-Fiメッシュは電力消費が大きいため、**ノードは常時接続しない**(→ [02_system_architecture.md](./02_system_architecture.md) の電力戦略)

## 6. 成功基準(プロジェクト全体)

1. 3台以上のステッカーがメッシュを形成し、スマホから一覧・設定できる
2. 貼った対象に応じた感情表示が「それらしい」と感じられる(家族・友人によるテスト)
3. ノードが電池で2週間動作する
4. ステッカーと呼べる形状(薄型カスタムPCB)の完成
