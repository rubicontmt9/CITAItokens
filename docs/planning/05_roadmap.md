## Phase 1 — 単体試作(スタンドアロン感情表示)

**内容**: 開発ボード1台で「センサー → 感情 → 電子ペーパー表情表示」を動かす。ネットワークなし。

**調達(1台分, 約5,700円)**: XIAO ESP32S3 / Waveshare 1.54" e-Paper V2 / AHT20 / LIS3DH / BH1750 / LiPo 500mAh / ブレッドボード類(詳細: [03_hardware_design.md](./03_hardware_design.md#1-試作フェーズのbom開発ボード段階))

**タスク**:
1. PlatformIOプロジェクト作成(`software/firmware/`)、ピン割当の実機確認(特にLIS3DH INTのRTC起床可否)
2. 各センサーの読取とシリアル出力
3. GxEPD2で表情ビットマップの全面/部分書き換え
4. 感情エンジンv1(特徴量→Valence-Arousal→8表情)+ ネイティブユニットテスト
5. ディープスリープ + タイマー/振動起床の動作確認

**DoD**:
- [ ] 温める/揺らす/暗くする/放置するの各操作で、対応する表情に数秒以内に変化する
- [ ] ディープスリープから振動割り込みで起床し「びっくり」を表示できる
- [ ] 感情エンジンのユニットテストがCIまたはローカルで通る

## Phase 2 — メッシュ + ゲートウェイ + Webアプリ

**内容**: 3台構成(ノード2 + ゲートウェイ1)でメッシュ通信とスマホからの確認・設定を実現する。

**調達**: 追加2台分(約11,000円)

**タスク**:
1. painlessMeshでノード⇄ゲートウェイのreport/config同期(JSONプロトコル実装)
2. ゲートウェイ: `setRoot` + `stationManual` によるルーターブリッジ、NTP、mDNS
3. ESPAsyncWebServer + WebSocketでWeb UI(ホーム/詳細/設定)
4. 初回セットアップAPモード(キャプティブポータル)
5. 設定rev同期(Web UIで変更 → ノードに反映)の一連の動作確認

**DoD**:
- [ ] スマホブラウザから `http://persona.local` で3台の表情・センサー値が一覧できる
- [ ] Web UIで名前・性格を変更すると、次回同期でノードの挙動・表示が変わる
- [ ] ノード1台の電源を切ってもメッシュが自己修復し、残りの台の報告が継続する

## Phase 3 — 電力最適化

**内容**: 電池寿命目標(2週間)の達成。実測に基づく最適化。

**タスク**:
1. スリープ電流・起床サイクル電力の実測(USB電流計 or PPK2)、[03の電力収支表](./03_hardware_design.md#3-電力収支の概算)を実測値で更新
2. 報告周期のデフォルト5分化、「N回に1回同期」モードの実装
3. メッシュjoin時間の短縮(チャンネル固定・親ノードヒントのRTC保存)
4. 電池電圧監視と「おなかすいた」表示・Web UIでの電池警告

**DoD**:
- [ ] 実測ベースの試算で電池寿命2週間以上(500mAh)
- [ ] 1台を実運用し、1週間後の実残量が試算と大きく乖離しない

## Phase 4 — カスタムPCB + ステッカー筐体

**内容**: 仕様確定した回路をKiCadで薄型基板化し、ステッカー形状に仕上げる。

**タスク**:
1. KiCadプロジェクト作成(`hardware/schematic/`, `hardware/pcb/`)。使用KiCadバージョンを `hardware/README.md` に明記
2. 回路設計: ESP32-S3-WROOM-1(技適済)/ FPC直結e-Paper + 駆動回路 / MCP73831充電 / 低Iq LDO / センサーチップ実装
3. レイアウト: 55×45mm・総厚10mm以下、アンテナキープアウト遵守
4. `hardware/bom/` にBOM CSV、`hardware/pcb/gerbers/` に製造データ出力 → 基板発注(JLCPCB等)・実装・動作確認
5. 外装(薄枠3Dプリント or ラミネート)と貼付方法(再剥離テープ)の検討

**DoD**:
- [ ] カスタム基板上でPhase 3までの全機能が動作する
- [ ] 外形が目標サイズ(約55×45mm・厚10mm以下)に収まる
